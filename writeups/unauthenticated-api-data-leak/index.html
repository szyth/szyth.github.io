An unauthenticated API leaking every user on the platform

May 11, 20222 min read#pentest#api

The scope of work and its details are redacted under the rules of engagement.

Introduction

The web application was an exam portal where faculty can create and schedule online exams, then invite and assign tests to students. Students log in and take their exams.

Burp, my old friend

  • I set up the Burp proxy to intercept all my requests to the portal.
  • I started with dynamic analysis of the application: its flows, and how I might tamper with its logic.
  • In situations like this, the OWASP Testing Guide is a helpful checklist to keep by your side.
  • I tested several checks (input validation, fuzzing) but found nothing interesting.
  • Giving the application a pause, I went looking through Burp's history for anything interesting.
  • I started playing with the HTTP request headers to try to break the logic.
  • First I watched every status code and the response that came with it. Nothing interesting there either.
  • Tampering further, I played with Authorization: Bearer <token>.
  • Changing a few characters in the token made no difference: I got the same results as with the real token.
  • I removed the whole Authorization header and, guess what, still got the same results.

@_@

  • The API was leaking critical-severity data to unauthenticated users.
  • I went hunting for other affected APIs.
  • In total, 6 APIs leaked data. One was the users API shown above, which exposed the PII of all ~1000 users on the platform:
    • Names
    • Email addresses
    • Phone numbers
    • Addresses
    • User IDs (see how I used these for a Super Admin privilege escalation)

Impact

1. Sensitive data exposure

Exposed personal data can be used to identify individuals, directly or indirectly, for malicious purposes.

2. Financial loss

Costs can include compensating affected customers, incident response, investigating the breach, new security measures, legal fees, and regulatory penalties for non-compliance with laws such as the GDPR.

3. Reputational damage

Once an organisation's integrity is compromised, users start to see it as untrustworthy, even after the exposure is fixed, and become hesitant to share personal information.

Remediation

  • Validate the token on the server before sending any data back to the client.
